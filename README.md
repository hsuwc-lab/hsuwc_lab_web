# 編輯者

需要 GitHub 帳號且是實驗室 Organization 的成員。

## 網站怎麼運作

內容全部放在研究室共用 Google 帳號的雲端硬碟。每天凌晨 3 點多，GitHub 會自動把試算表與照片抓下來、更新網站。
急的話可以手動更新（見下方「馬上更新網站」）。

## 馬上更新網站的方法

1. 打開這個 repo → 上方「Actions」
2. 左邊點「Sync and deploy」
3. 右邊「Run workflow」→ 綠色「Run workflow」
4. 約一分鐘後變成綠勾，重新整理網站就看得到（看不到請用無痕視窗）

每個試算表的「說明」分頁有各欄位的填法。

### 填試算表的規則

- **第一列是欄位名稱，不要改、不要刪**。網站靠欄位名稱讀資料
- 有下拉選單的欄位請用選的，不要自己打字
- `_zh` 是中文、`_en` 是英文。只填一種也可以，網站會自動用另一種補上
- `id` 每列都要有，而且不能重複；**已經上線的 id 不要改**，網址與關聯都靠它
- members 的 `show` 沒勾的人不會出現在網站上（連姓名都不會公開）
- 不想公開的東西（電話、學號、備註）可以放在表格最右邊自己加的欄，網站只讀固定的欄位

### 照片

- 檔名要和試算表 `photo` 欄填的一模一樣（含副檔名，例如 `m-2025-wang-xiaoming-ms.jpg`）
- JPG 或 PNG 都可以，尺寸不用自己縮，同步時會自動裁切壓縮
- **同一個檔名只會下載一次**。要換照片，請用新檔名（例如 `m-2025-wang-xiaoming-ms-2.jpg`）並更新試算表
- 舊照片可以從雲端移走，網站上已經有的不會消失

## 出錯了怎麼辦

**網站不會壞**：同步失敗時，網站會繼續顯示上一次成功的內容。

到 Actions 頁點紅色叉叉的那筆 → 點「build」→ 展開紅叉的步驟，看最後幾行。

| 訊息 | 意思 | 怎麼辦 |
| --- | --- | --- |
| `❌ … id 重複` | 兩列用了同一個 id | 改掉其中一列的 id |
| `❌ … 缺少欄位` | 第一列的欄位名稱被改了或刪了 | 對照 `docs/templates/` 的範本改回來 |
| `⚠️ … 找不到照片` | 檔名和試算表不一樣 | 檢查大小寫、副檔名、空格（這是警告，網站仍會更新） |
| `403`、`permission` | 試算表或資料夾沒分享給同步帳號 | 請維護程式的人處理（見 DEVELOPER.md） |

# 自動更新失效

較久沒有人動 repo 時(約60天)，GitHub 會停用定時。
到 Actions → 「Sync and deploy」→ 按「Enable workflow」即可。
